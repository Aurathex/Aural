# Aural v0.2 · A — Adaptive STT + Hardware Test: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aural measures what this PC can run (CPU, NVIDIA/AMD GPU), offers more models in more variants, and labels them from real measurements in plain language.

**Architecture:**
- The catalog moves to v2. A model is a downloadable file set at one precision; each model lists **variants** (runtime + backend). A variant id is `<model>@<backend>`.
- The two existing worker processes gain GPU backends: ONNX Runtime with DirectML, whisper.cpp with Vulkan. They also gain new engines (Parakeet v3, Moonshine) and a stats message for memory.
- A new `aural-eval` crate holds WER scoring, metrics and the built-in test clips, shared by the bench tool and the app.
- The app runs a Hardware Test: detect → calibrate with probe models → estimate → measure on download. Labels come from one pure function.

**Tech Stack:** Rust 1.98.1, transcribe-rs 0.3.11 (onnx + ort-directml), whisper-rs 0.16 / whisper.cpp 1.8.3 (vulkan), windows 0.62 (DXGI), Tauri 2.11 + Svelte 5, claxon (FLAC decoding), Vitest.

**Spec:** `docs/superpowers/specs/2026-09-26-aural-v0.2-a-adaptive-stt-design.md` (+ roadmap `2026-09-26-aural-v0.2-roadmap.md`).

## Global Constraints

- Local only: no cloud STT/AI/processing, no telemetry. Network only for downloads the user starts, from pinned URLs verified by SHA-256.
- Preserve v0.1: `Transcriber`/`Engine`/`Backend` abstraction, worker isolation, installer, hook recovery, clipboard restore, restart-after-update, Delete Aural, and every existing test (the full `verify.ps1` suite stays green).
- Models and extra runtimes are optional downloads. Only small test assets (≤ 2 MB of clips, the probe models are downloaded) ship in the installer.
- License stays PolyForm Strict 1.0.0. New dependencies must pass `cargo deny check`. New models need a license suitable for Aural, credited in `THIRD_PARTY_NOTICES.md` and the About page.
- **Plain language** (spec §5.1): everyday words by default; the jargon list (WER, RTF, VRAM, DirectML, Vulkan, ONNX, ggml, int8, fp16, fp32, q5_0, q8_0, backend, inference) appears only inside "Technical details".
- No silent CPU fallback: a requested GPU backend that can't start is an error.
- Engines `onnx` and `ggml` stay mutually exclusive per binary.
- Visual language: minimal, black/white/neutral, keyboard and screen-reader accessible.
- Commits: Conventional Commits, one logical change each, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nothing pushed or merged.

## Review Focus

1. **Upgrading from v0.1 with a model installed:** the saved model still works after the first start of v0.2, without re-downloading and without the hardware test being required first. → Task 2 test `v01_settings_get_a_cpu_variant`, Task 11 test `v01_install_keeps_working_before_the_hardware_test`.
2. **A GPU backend that fails at runtime** (driver crash, removed eGPU) must not strand the user without dictation. → Task 11 test `gpu_failure_falls_back_to_recommended_cpu_with_notice`.
3. **Hybrid laptops with two GPUs** (Intel iGPU + NVIDIA): variants must run on, and be labelled for, the discrete GPU, and the report must say which GPU. → Task 7 test `discrete_gpu_preferred_over_integrated`.
4. **Estimates that are badly wrong** must not become "Recommended" over a measured variant. → Task 9 test `measured_beats_estimated_on_ties_and_estimates_need_margin`.
5. **Declining the probe download** leaves a usable app with plain explanations and no labels. → Task 11 test `declined_probe_shows_detection_only`.
