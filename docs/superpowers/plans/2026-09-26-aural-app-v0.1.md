# Aural app v0.1 — brief plan

**Spec:** docs/superpowers/specs/2026-09-25-aural-design.md (approved). This plan pulls
parts of M1 (core loop), M2 (pill), M3 (models + settings), M5 (settings) and M6
(distribution) forward at the user's explicit direction (2026-09-26), before the M0
benchmark gate closes. Branch `app-v0.1`, based on `worktree-m0-bench`. **No merge to
`main`:** the M0 gate (user review of benchmark results) is still open.

## Goal
A real Windows app, installed normally, that does the core loop: hold hotkey → speak →
release → local STT → text pasted into the focused app. It also has a polished settings
window, a tray icon, the listening pill, model management, start-with-Windows, a guarded
"Delete Aural" action, an NSIS installer, and WinGet manifests.

## Constraints carried from the spec
- Tauri v2 (2.11.x stable, not 3.0-alpha) with a Svelte 5 + TypeScript UI. Rust owns all
  state.
- STT runs in separate worker processes over framed stdin/stdout IPC. ONNX and ggml
  engines never link into one binary.
- No network except user-initiated downloads. No telemetry. Audio stays in memory.
- Black, white and neutral palette; Segoe UI Variable; no gradients or "AI glow".
- Keep `aural-bench` and the engine adapters working. The M0 tests must stay green.

## Phases (each ends green: fmt, clippy -D warnings, tests)
1. **Engines crate.** Move the `Transcriber` trait, adapters and WAV loading from
   `tools/bench` into `crates/aural-engines` (features onnx/ggml). Bench re-exports them,
   so its API and tests are unchanged.
2. **Core crates (TDD).**
   - `aural-core`: settings with atomic save, defaults and corrupt-file backup; a pure
     session state machine; errors; paths with an `AURAL_DATA_DIR` override for tests.
   - `aural-models`: catalog, install receipts, resumable sha256-verified download,
     removal guards, recommendation.
   - `aural-audio`: device list, capture, resample, level bands, silence gate.
   - `aural-platform`: low-level hotkey hook and chord matcher, clipboard-paste insertion
     with modifier/focus/elevation guards, autostart registry, GPU detection.
   - `aural-stt-protocol` with the client, plus worker binaries `aural-stt-onnx` and
     `aural-stt-ggml`.
3. **Brand and design.** Logo (speed + clarity + flowing water) as SVG plus ICO/PNG set.
   Use `/reimagine-it` variations and audit on HTML mocks of the pill and settings, then
   implement the chosen direction.
4. **Tauri app.** Tray menu; settings window with General (hotkey, mode, start with
   Windows), Microphone (device plus live level test), Models (catalog, status,
   download/remove/use), and About & Privacy (licenses, Delete Aural). Pill window that
   takes no focus and has real level bars. An orchestrator wires hotkey → capture →
   worker → insertion.
5. **Delete Aural.** Modal shows "Are you sure you want to delete Aural?". The button is
   enabled only after the user types exactly `YES, DELETE`, and the backend re-checks the
   same string. The action removes data, models, settings and autostart, then runs the
   NSIS uninstaller silently if installed.
6. **Distribution.**
   - Tauri NSIS installer, per-user, no admin.
   - `release.yml` builds a draft GitHub Release with the installer and SHA256SUMS.
   - WinGet manifests `Aurathex.Aural` (schema 1.10.0) checked with `winget validate`,
     plus a submit workflow (wingetcreate, manual trigger, needs a PAT secret).
7. **Licensing.** Write the legal-implications analysis. Switch the license to PolyForm
   Noncommercial 1.0.0 in one isolated commit that is flagged for approval before
   publication.
8. **Verification on the laptop.**
   - All tests, builds and clippy.
   - UI rendered in the browser pane with a mocked backend (screenshots).
   - Real app launch, tray and window checks.
   - Installer silent install → launch → uninstall.
   - Delete-flow integration test against temp dirs.
   - Autostart registry round trip.
   - Hotkey/insertion smoke tests where automatable.
   - A final fresh-reviewer pass.

## Deliberate v0.1 limits (spec §24 still applies)
- Engines are CPU-only. Vulkan/CUDA builds need SDKs and stay behind features for later.
- Insertion is clipboard-paste only, with guards. When the clipboard can't be restored,
  the fallback is to type the text. Per-app rules come later.
- No auto-update, no streaming partial results, no LLM cleanup.
