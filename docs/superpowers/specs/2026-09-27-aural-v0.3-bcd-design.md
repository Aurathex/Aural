# Aural v0.3: live transcription, text pipeline, local data (sub-projects B, C, D)

Built on branch `v0.3` from `v0.2` (sub-project A). Written alongside the implementation at
the owner's request ("implement and test the work, then report"), so this records the
design as built. Rules from the roadmap apply: local only, incremental, optional
downloads with consent, PolyForm Strict unchanged, tests first, plain language.

## B. Live transcription

### Goal

Words appear while the user speaks; the final text is typed once when they finish. Live
text never types anything itself, never duplicates text, and never loses a dictation when
it fails.

### How it streams

One abstraction for every engine, in `aural_engines::live::LiveSession`:

- **Native** (`Transcriber::stream`, the `Stream` trait): the engine encodes audio as it
  arrives and never encodes the same audio twice. Moonshine Streaming (tiny, small; MIT)
  does this. transcribe-rs 0.3.11 already had the incremental frontend/encoder but kept it
  private; the vendored copy adds a public live-stream API (documented in
  `third_party/transcribe-rs/AURAL-PATCH.md`). The decoder re-reads the encoded audio for
  each update, and stops at 448 tokens (about 70 s of speech), so the stream is closed —
  its text kept once — and a new one opened at each pause, at the first quiet moment after
  20 s, and at the latest after 28 s. Each update's cost is bounded by the phrase, and a
  long dictation keeps its end.
- **Phrases**, for engines that only read whole recordings (Parakeet, Whisper, Moonshine
  base/tiny): the recording is split at pauses (600 ms below about -40 dBFS). A finished
  phrase is read once and never again; only the phrase being spoken is re-read, every
  300 ms of new audio. A phrase with no pause is cut at its quietest 100 ms after 20 s, so
  each read is bounded by the phrase, not the recording. **Limitation, stated in the
  app:** this is re-reading the current phrase, not true streaming; words settle at each
  pause, and a phrase boundary can change capitalization or punctuation compared with
  reading the whole recording at once.

Text comes in two parts: *stable* (finished phrases, plus leading words two consecutive
reads agree on, ignoring case and punctuation) and *tentative* (words a later read may
still correct). The final text is `LiveSession::finish`: every phrase exactly once.

### Where it runs

- `aural-audio::capture::start_live` hands the recording to a callback as 16 kHz pieces
  while it happens (`StreamResampler`, sample-identical to resampling the whole recording),
  ending with the last piece before `stop` returns. The start cue is muted out of the
  pieces exactly as out of the recording.
- The worker protocol (v3) gains `LiveBegin` / `LiveAudio` / `LiveEnd` / `LiveCancel`; the
  `LiveSession` lives in the worker, next to the engine. The client keeps one request in
  flight; audio that arrives meanwhile goes in the next push. Live requests are never
  retried.
- In the app, `live::LiveFeed` (a thread per dictation) streams to the worker and emits
  `live` events to the pill. The dictation loop is unchanged in shape: on stop it takes
  `live_finish()`; if the stream failed, or returned nothing for real speech, it
  transcribes the whole recording the v0.2 way (with its restart-and-retry). Cancel, a
  too-short tap and a silent recording call `live_cancel()`.
- Live text runs only when "Show words while I speak" is on (default on), the app in front
  doesn't turn it off, and the model keeps up on this PC (RTF ≤ 0.3, the same bar as the
  "Live text" label). General shows which of these applies, in plain words.

### Pill

With live text the pill window also holds a caption (440 × 58 DIP) above the pill (below
it when the pill is at the top); the pill itself stays where it always was. Stable words
are white, tentative words grey; the newest words stay visible, older lines scroll off.
The caption clears for each new recording and when the text is inserted, fails or the
pill hides; late events after the recording ended are ignored.

## C. Text pipeline

Every transcript, live or not, goes through `polish` before it is typed:

1. **Profile** for the app in front when the user stops (its program file, e.g.
   `slack.exe`; nothing is hard-coded, unknown or undetected apps use the general
   settings). A profile can set tidy-up, dictionary, live text and history.
2. **Dictionary** (`dictionary.json`): spellings ("Aurathex") and "when I say" phrases,
   whole words, case-insensitive, longest phrase first.
3. **Tidy-up** (default **Off**, so v0.2 output is unchanged):
   - *Light*: remove hesitations (um, uh, erm, hmm), fix spacing and the first capital.
     Meaning words ("like", "you know") stay.
   - *AI*: a local language model rewrites the light result. Its answer is used only if
     `aural_text::rewrite::check` accepts it: every protected token kept exactly
     (addresses, numbers, code, paths, mixed-case identifiers, acronyms, backticked
     text), none invented, **the same words in the same order** (only punctuation,
     capitals, spacing, hesitations and a word said twice in a row may change, so a
     dropped "not" or an added "can't" is refused), not a reply ("Sure, here is…").
     Otherwise the light result is typed. The dictation is marked as
     data (`<dictation>` tags) and worked examples show requests being tidied, not
     answered.

Protected tokens are never changed by any step.

### AI model

- Qwen2.5-0.5B-Instruct (Apache-2.0), 4-bit ONNX export by onnx-community, 793 MB, in
  its own small catalog (`manifests/text-models.json`, pinned commit + SHA-256), so it
  never appears among speech models or in the hardware check. The int8 exports of the
  0.5B and 1.5B models answered instead of tidying in tests and are not used.
- Downloaded only when the user presses "Download 793 MB" on the Writing page; resumable
  and checked like speech models; removable.
- Runs in its own process of the ONNX worker binary (protocol v4 `LoadText` / `Generate`),
  only while AI tidy-up is in use. Greedy decoding with a key/value cache; the shared
  instructions and examples are cached between dictations. A rewrite that takes longer
  than 12 s is abandoned for the light result.

## D. Local data

- **History** (`history.jsonl`, text only, never audio): on by default, kept 30 days
  (7 days / 30 days / 1 year / until deleted), pruned at start and on save; search (all
  words, any case), copy, fix, delete one, delete all; apps can be left out by profile.
- **Statistics** (`stats.json`, numbers only): dictations, words, time spoken per day
  (UTC), per model variant and per app; words per minute; a two-week chart. Can be turned
  off or reset.
- **Personal learning** (`dictionary.json`): when the user fixes a dictation in History,
  replacements of up to three words between what Aural wrote and the fix become
  suggestions ("or a thex" → "Aurathex", with a count). Nothing applies until the user adds
  a suggestion to the dictionary; dismissed ones are not suggested again; everything
  learned can be forgotten in one click.
- All files live under Aural's data/config folders and are removed by Delete Aural.
  Nothing is sent anywhere.

## Settings UI

Two new pages, Writing and History, in the existing design. The settings window has one
scroll area (the content pane); the window itself never scrolls (fix for sr-only spans
that escaped the pane and stretched the document into blank space). About names Aurathex
as the maker with the installer's copyright line.

## Testing

Unit tests for every new module (live session, feeder, resampler, protocol messages,
dictation loop hooks, text crate, text catalog, UI wording and caption state); real-model
tests (Moonshine Streaming native streaming, Parakeet and Whisper phrase mode through the
real workers, AI tidy-up battery through the real worker); a real-audio test that plays
speech into a virtual microphone and runs Aural's capture, feeder, worker and model.
