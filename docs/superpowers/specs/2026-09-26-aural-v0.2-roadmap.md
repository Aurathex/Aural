# Aural v0.2 — roadmap

v0.2 is built from the `app-v0.1` branch as four sub-projects, in this order. Each has its
own spec, implementation plan, tests and review. v0.2 is released only when all four are
done and the owner has approved a final report.

| # | Sub-project | Spec | Depends on |
|---|---|---|---|
| A | **Adaptive STT + Hardware Test**: catalog v2 (Model + Runtime + Backend + Precision), GPU backends (DirectML, Vulkan), new models, hardware test, benchmark-based labels | `2026-09-26-aural-v0.2-a-adaptive-stt-design.md` | — |
| B | **Live transcription**: partial text while speaking, streaming engines, pill updates | written when A is done | A (streaming variants) |
| C | **Text pipeline**: custom dictionary, app-aware profiles, optional local LLM cleanup with a replaceable backend | written when B is done | A (runtimes), B (final-text hook) |
| D | **Local data**: searchable history, analytics, personal learning, with delete/reset controls | written when C is done | C (corrections to learn from) |

## Rules for every sub-project

- **Local only.** No cloud STT, no cloud AI, no cloud processing, no telemetry. The network
  is used only for downloads the user starts (models, runtimes), from pinned URLs checked
  against SHA-256.
- **Incremental.** Keep v0.1's engine abstraction (`Transcriber`, `Engine`, `Backend`), the
  worker-process isolation, the installer, the reliability features (hook recovery,
  clipboard restore, restart after update, Delete Aural) and every existing test.
- **Optional downloads.** Models and any extra runtimes are downloaded on demand, never
  bundled, except small test assets.
- **License.** Aural stays under PolyForm Strict 1.0.0. Every new dependency, model and
  runtime has a license compatible with being used by Aural and is credited in
  `THIRD_PARTY_NOTICES.md` and the About page.
- **Tests first** for every behaviour (superpowers:test-driven-development), and
  verification with evidence before any completion claim.
- **Nothing is pushed, merged or published** without a final report and the owner's
  approval.

- **Plain language.** Every feature must be understandable by non-technical users: everyday words by default, technical terms only under "Technical details", errors that say what happened and what to do. See spec A section 5.1; B, C and D follow the same rule.
